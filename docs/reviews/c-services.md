# Review of task C (Notifications, AI, Voice)

## Round 1 (Antigravity)

### Review of `main..task/c-services`

Verified read-only against the codebase, live Omarchy 4.5 scripts/shell plugin (`/usr/share/omarchy/shell/plugins/notifications/`, `/usr/bin/omarchy-*`, `/opt/superwhisper/`), Maprisma reference sources, and `python3 -m unittest discover -s tests` (143 tests OK).

#### Findings

1. **Medium** — [services_core.py:1043-1084](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/services_core.py#L1043-L1084), [test_services_core.py:685-690](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/tests/test_services_core.py#L685-L690): **Three Superwhisper setters run `superwhisper … show` before checking whether `superwhisper.service` is active, auto-starting a stopped service.**
   - **Scenario:** Per the Superwhisper CLI contract (`superwhisper/SKILL.md:15-17` and [services_core.py:931-932](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/services_core.py#L931-L932)), every `superwhisper` command starts `superwhisper.service` when it is not running. If the Voice page was opened while Superwhisper was running, the user then stops `superwhisper.service` from the bar panel/tray, and subsequently changes Language, Microphone (to a named device), or Processing mode, `sw_set_language()` (line 1047), `sw_select_microphone()` (line 1064), and `sw_select_mode()` (line 1081) invoke `_sw_json(...)` (`superwhisper general|audio|models show`) *before* `_sw_run()` checks `_service_active("superwhisper.service")` (line 1037). That auto-starts the daemon and models instead of refusing. `test_superwhisper_setters_refuse_when_not_running` only tests `sw_set_tone` and `sw_set_switch` (the two setters that do not call `_sw_json` first).
   - **Fix:** Guard `_service_active("superwhisper.service")` before calling `_sw_json(...)` in `sw_set_language`, `sw_select_microphone`, and `sw_select_mode` (or check it inside `_sw_json()` / a shared helper). Extend `test_superwhisper_setters_refuse_when_not_running` to cover all five `sw_*` setters and assert no `superwhisper` command is called at all.

2. **Medium** — [services_core.py:404-418](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/services_core.py#L404-L418): **`SHIPPED_HELPERS` includes helpers whose catalog `ask` definition is `null` (`gemini`, `opencode`, `goose`).**
   - **Scenario:** In Maprisma's `helpers_shipped.g.dart` (v2, lines 55–59, 94–98, 161–165) and `maprisma/data/helpers.json` (v3), `gemini`, `opencode`, and `goose` all have `"ask": null` and are excluded by `helpers_catalog.dart:38` (and by `services_core.catalog_helpers()` lines 458–460 when reading `helpers.json`). On this live Omarchy 4.5 system, `/usr/lib/maprisma/data/helpers.json` does not exist, so `catalog_helpers()` falls back to `SHIPPED_HELPERS`; because `opencode` is installed here, `helper_states()` reports `opencode` as `installed=True, ready=True` (`"OpenCode (untested)"`) and offers it in **AI helper for all Maprisma apps**. Picking it writes `"helper": "opencode"` to `~/.config/maprisma-ai/settings.json`, which Maprisma apps cannot use for Ask AI (silently falling back to another helper).
   - **Fix:** Remove `("gemini", "Gemini CLI", "gemini")`, `("opencode", "OpenCode", "opencode")`, and `("goose", "Goose", "goose")` from `SHIPPED_HELPERS` so the fallback matches the 10 helpers in `helpers_shipped.g.dart` that actually have a valid one-shot `ask` argv.

3. **Medium** — [services_core.py:885-908](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/services_core.py#L885-L908): **`sw_audio()` does not filter out disconnected or unavailable microphones.**
   - **Scenario:** `sw_audio()` skips `dev.get("ignored") is True` (line 893), but does not filter `dev.get("availability") in ("disconnected", "not available")`, unlike Superwhisper's own Omarchy panel (`/opt/superwhisper/assets/omarchy-plugin/superwhisper-panel/status.py:167`). When a USB/Bluetooth/dock microphone is unplugged, Superwhisper still returns it in `devices` with `"availability": "disconnected"` (or `"not available"`), and rejects selecting it (`"Requested microphone is ignored, disconnected or unavailable"` in `/opt/superwhisper/bin/superwhisper`). Both the Voice page's Microphone dropdown and `sw_select_microphone()` accept such devices, leading to a guaranteed CLI error on selection.
   - **Fix:** Skip entries where `dev.get("availability") in ("disconnected", "not available")` in `sw_audio()`, and add a unit test verifying disconnected/unavailable devices are omitted and rejected by `sw_select_microphone()`.

4. **Medium** — [pages_services.py:572-580](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L572-L580) (and [pages_services.py:588-596](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L588-L596)): **Superwhisper `Language` (and `Microphone`) combo row misdisplays an unlisted saved value as index 0 and blocks switching directly to it.**
   - **Scenario:** When Superwhisper's saved `config.language` is not supported by the active offline mode (e.g. `"ja"` or `"el"` after switching from Cloud to Offline Lite — documented in `superwhisper/SKILL.md:74-76` and `PROTOCOL.md:21`), line 576 falls back to `current = values[0]` (`"auto"`, shown as **Automatic**). The UI falsely shows **Automatic** even though the saved language is still `"ja"` (dictating in English), and because `_on_combo()` ([pages_services.py:202-212](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L202-L212)) initializes `start = [0]` and returns early on `index == start[0]`, the user cannot pick **Automatic** directly to fix it without first picking another language. The same occurs on line 593 if a saved non-default microphone is not in `values` and falls back to `""` (`System default`, index 0).
   - **Fix:** Follow the pattern already used on the AI page ([pages_services.py:379-381](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L379-L381)): when `details.get("language")` is non-empty and not in `values`, append it to `values`/`labels` (e.g. using `options.languageLabel` or the code with a "(not supported in this mode)" suffix) and select that entry so the real saved setting is shown and **Automatic** is directly selectable. Do likewise when `config.audioInputDeviceId` is set with `useDefaultInputDevice: false` and not in `devices`.

5. **Low** — [pages_services.py:220](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L220), [239](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L239), [278](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L278), [306](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L306), [335](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L335), [373](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L373), [404](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L404), [422](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L422), [452](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L452), [474](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L474), [491](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L491): **Translated `Adw.PreferencesGroup` titles are not wrapped in `escape()`.**
   - **Scenario:** Libadwaita's `adw-preferences-group.ui` sets `use-markup="True"` on both the `title` and `description` `GtkLabel`s, and `docs/plan-maprisma-parity.md` Rule 5 requires wrapping translated Adw group titles in `ui_helpers.escape()`. None of the current 7 translation files contain `&` or `<` in those 11 titles, so nothing breaks today, but any future translation containing `&` (e.g. `"On screen & history"`) will fail Pango markup parsing and render an empty heading.
   - **Fix:** Wrap all translated `Adw.PreferencesGroup(title=escape(_(...)))` calls consistently with `description=escape(...)`.

6. **Low** — [pages_services.py:350-359](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L350-L359): **`_set_dnd()` does not guard against overlapping toggles or stale revert callbacks.**
   - **Scenario:** Unlike `_act()`, `_set_dnd()` neither disables the switch while in flight nor tracks a generation/token. Clicking the **Do not disturb** switch twice rapidly spawns two concurrent `omarchy-shell notifications setDnd` processes with no ordering guarantee; if the first call fails after the second toggle or finishes out of order, `revert(not want)` flips the switch opposite to the user's latest intent or leaves the switch out of sync with the shell.
   - **Fix:** Disable the switch while the async call is in flight (or route through `_act(..., refresh=True)` / check a per-toggle sequence counter before reverting or toasting).

7. **Low** — [services_core.py:640-652](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/services_core.py#L640-L652): **`read_shared_ai()` follows a symlinked `AI_DIR` parent directory while `update_shared_ai()` refuses it.**
   - **Scenario:** `update_shared_ai()` opens `AI_DIR` via `_private_dir()` with `O_DIRECTORY | O_NOFOLLOW` (refusing a symlinked `~/.config/maprisma-ai`), whereas `read_shared_ai()` calls `_read_json(AI_DIR / "settings.json", MAX_AI_FILE)`, where `O_NOFOLLOW` applies only to the final path component. If `~/.config/maprisma-ai` is a symlink to a directory containing a valid `settings.json`, the AI page shows it as healthy (`broken=False`) and leaves the helper and web-search controls active until a write fails with `ELOOP`.
   - **Fix:** Open `AI_DIR` with `O_RDONLY | O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC` (or reject `AI_DIR.is_symlink()`) inside `read_shared_ai()` and read `settings.json` relative to that directory fd with `_read_at()`.

8. **Low** — [pages_services.py:401](file:///mnt/Data/Projects/omarchy-settings-manager-wt/c-services/pages_services.py#L401): **Home-path shortening uses raw substring replacement (`path.replace(str(sc.HOME), "~", 1)`).**
   - **Scenario:** If `HOME=/home/uwe` and `XDG_CONFIG_HOME=/home/uwe-alt/.config` (or `/tmp/home/uwe/cfg`), the note renders `Saved in ~-alt/.config/maprisma-ai/settings.json` (or `Saved in /tmp/~/cfg/...`).
   - **Fix:** Check a directory-boundary prefix (e.g. `Path(path).is_relative_to(sc.HOME)`) before replacing the leading home path with `~`.
