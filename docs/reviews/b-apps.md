### Findings

1. **Medium** — [apps_core.py:77](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/apps_core.py#L77) (`_UPDATE_LINE_RE` / `parse_update_lines`)
   - **Failure scenario:** Verified live on this Omarchy 4.5 machine (`yay v13.1.0`): `yay -Qua` prints `artcraft-launcher 0.20.1-1 -> 0.20.3-1 [1h6m]` with a trailing bracketed tag. Because `_UPDATE_LINE_RE` anchors the new version directly to end-of-line (`\Z`), `parse_update_lines()` drops the line and live `check_system_updates()` returns `aur: {}`, hiding real AUR updates.
   - **Suggested fix:** Allow optional trailing bracketed annotations in `_UPDATE_LINE_RE` (e.g., `(?:\s+\[[^\]]{1,40}\])?\Z`, skipping `[ignored]` lines if present) and add a regression test with `artcraft-launcher 0.20.1-1 -> 0.20.3-1 [1h6m]` in [tests/test_apps_core.py](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/tests/test_apps_core.py).

2. **Medium** — [apps_core.py:288](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/apps_core.py#L288), [apps_core.py:775](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/apps_core.py#L775) (`scan_desktop_entries`, `open_argv`)
   - **Failure scenario:** Verified live on this machine: `~/.local/share/applications/` contains three Omarchy web apps whose filenames include spaces (`Google Contacts.desktop`, `Google Maps.desktop`, `Google Photos.desktop`). `scan_desktop_entries()` filters every entry with `system_core.valid_desktop_id()`, whose regex ([system_core.py:73](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/system_core.py#L73)) forbids spaces and `()&,'@+`, silently dropping all three web apps from System apps—even though `WEBAPP_NAME_RE` ([apps_core.py:71](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/apps_core.py#L71)) and `test_launcher_names` ([tests/test_apps_core.py:126](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/tests/test_apps_core.py#L126)) explicitly allow `"Google Maps"` and `"Apple TV (4K)"`. `open_argv()` at line 775 also gates desktop-id launches on `system_core.valid_desktop_id()`, so once scanned, "Open" would still be omitted for those web apps.
   - **Suggested fix:** Add a local `valid_entry_id()` helper in [apps_core.py](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/apps_core.py) accepting either `system_core.valid_desktop_id(desktop_id)` or a top-level `.desktop` filename whose stem satisfies `valid_launcher_name()`, and use it in `scan_desktop_entries()` and `open_argv()` (keep autostart at [pages_apps.py:520](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/pages_apps.py#L520) gated on `system_core.valid_desktop_id()` since `system_core.add_autostart` requires it).

3. **Medium** — [pages_apps.py:139-143](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/pages_apps.py#L139-L143), [pages_apps.py:427-440](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/pages_apps.py#L427-L440) (`check_updates`, `_update_of`)
   - **Failure scenario:** After starting an update in the terminal, the toast instructs `"Refresh the page when it is done."` ([pages_apps.py:686](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/pages_apps.py#L686)). If the user clicks Refresh within 60 seconds (`UPDATE_RECHECK_SECONDS = 60`), `check_updates()` skips rechecking and retains the old `self.updates` cache, and `_update_of()` returns the cached `(old, new)` pair without comparing it against the newly reloaded `app["version"]`. An already-updated package continues to show its `→ new` pill, "Update all", the old count, and a contradictory Details dialog (`Version: 6.1.1-1` next to `Update available: 6.1.0-1 → 6.1.1-1`) for up to 60 seconds.
   - **Suggested fix:** In `_update_of()`, suppress any cached update whose available version already equals `app.get("version")`, and clear or bypass the 60 s throttle on explicit user Refresh (or after a terminal action finishes).

4. **Medium** — [pages_apps.py:520-524](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/pages_apps.py#L520-L524), [pages_apps.py:704-719](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/pages_apps.py#L704-L719) (`system_menu`, `set_autostart`)
   - **Failure scenario:** `apps_core.autostart_ids()` ([apps_core.py:255-257](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/apps_core.py#L255-L257)) treats an existing `~/.config/autostart/<id>` file with `Hidden=true` or `X-GNOME-Autostart-enabled=false` (e.g., switched off on the Applications page via `system_core.toggle_autostart(id, False)`) as disabled, so System apps offers `"Start at login"`. Clicking it calls `system_core.add_autostart(desktop_id)`, which refuses existing regular files with `(False, "already in autostart")` ([system_core.py:1025](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/system_core.py#L1025)), showing `"That didn't work: already in autostart"`.
   - **Suggested fix:** When enabling autostart in `set_autostart()`, if `add_autostart(desktop_id)` fails with `"already in autostart"` (or when a regular file already exists at `AUTOSTART_DIR / desktop_id`), call `system_core.toggle_autostart(desktop_id, True)`.

5. **Low** — [apps_core.py:999-1000](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/apps_core.py#L999-L1000) (`read_maprisma_apps`)

7. **Low** — [pages_apps.py:609-610](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/pages_apps.py#L609-L610) (`confirm_uninstall`)

9. **Low** — [pages_apps.py:655-660](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/pages_apps.py#L655-L660) (`confirm_trash_older`)
   - **Failure scenario:** `size` on line 658 sums every entry in `app.get("older")` rather than only the `trashable()` entries kept in `files` on line 655. In addition, when the active AppImage is selected via symlink rather than newest version (as tested in `test_detection`, [tests/test_apps_core.py:633-658](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/tests/test_apps_core.py#L633-L658)), the dialog text `"the newest stays"` is inaccurate because a newer copy is in `older` and gets trashed.
   - **Suggested fix:** Filter `kept = [o for o in (app.get("older") or []) if apps_core.trashable(o["path"], apps_core.APPIMAGE_DIRS)]` once so `files` and `size` match, and say `"the active copy stays"` (or `"the one in use stays"`).

10. **Low** — [tests/test_apps_core.py:479-482](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/tests/test_apps_core.py#L479-L482) (`test_launch_is_detached_and_never_uses_run`)
    - **Failure scenario:** `Proc.wait(timeout=None)` raises `subprocess.TimeoutExpired` even when `timeout is None`. When `launch()` spawns the background reaper thread (`threading.Thread(target=proc.wait, daemon=True).start()` at [apps_core.py:803](file:///mnt/Data/Projects/omarchy-settings-manager-wt/b-apps/apps_core.py#L803)), that thread crashes with an unhandled traceback printed to stderr during every test run.
    - **Suggested fix:** In `Proc.wait`, raise `TimeoutExpired` only when `self.code is None and timeout is not None`, returning `0` when called with `timeout=None`.
